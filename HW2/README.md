# Трасса использования IR-инструкций (User <- Operand)

Pass `trace_pass.cpp` инструментирует логический модуль (`../HW1/app.c`, `-O2`) и во время работы приложения собирает трассу записей `User <- Operand`: для каждой выполненной инструкции (кроме `phi`) и каждого её операнда-инструкции пишется пара опкодов. Затем `log.c` на лету считает частоты окон из 1–5 подряд идущих записей.

## Файлы
- `trace_pass.cpp` — Pass (плагин нового Pass Manager, запускается в конце `-O2` пайплайна, `registerOptimizerLastEPCallback`)
- `log.c` — рантайм: функции `logUse`, `logFrame`, `registerOp`, подсчёт паттернов и вывод статистики
- `stats.txt` — статистика с раскрытием `phi` (задание со звёздочкой)
- `stats_no_phi_expand.txt` — статистика без раскрытия (`user <- phi` остаётся как есть)

## Как работает
- Перед каждой не-phi инструкцией вставляются вызовы `logUse(user_opcode, operand_opcode)`, по одному на операнд-инструкцию. Константы и аргументы функций пропускаются.
- **Задание со звёздочкой:** если операнд — `phi`, запись `user <- phi` заменяется записями для каждой инструкции, используемой в операндах этого `phi` (рекурсивно через вложенные `phi`, каждая инструкция один раз). Например, `shl <- phi` превращается в `shl <- add` и `shl <- sub`. Отключается переменной окружения `TRACE_EXPAND_PHI=0` при компиляции.
- Имена опкодов регистрируются один раз при входе в `app()` (`registerOp`).
- Перед каждым вызовом `simFlush` вставляется `logFrame()`: после `TRACE_FRAMES` кадров (по умолчанию 3, статистика собрана на 10) программа завершается и пишет статистику. При закрытии окна статистика пишется по сигналу `SIGABRT`.

## Сборка и запуск
```
sudo apt install clang llvm libsdl2-dev
make                      # Pass, обе версии приложения, stats.txt и stats_no_phi_expand.txt
make app_trace.ll         # инструментированный IR для просмотра
```
Окно можно не открывать: `SDL_VIDEODRIVER=dummy make`. Переменные рантайма: `TRACE_FRAMES`, `TRACE_TOP` (число паттернов на длину окна, по умолчанию 20), `TRACE_OUT`.

Вручную:
```
clang++ trace_pass.cpp -fPIC -shared -fno-rtti -I$(llvm-config --includedir) -o libTracePass.so
clang -O2 -fpass-plugin=./libTracePass.so -I../HW1 -c ../HW1/app.c -o app_trace.o
clang -O2 -I../HW1 app_trace.o log.c ../HW1/sim.c ../HW1/start.c -lSDL2 -o trace-app
./trace-app
```

## Результаты (10 кадров, 46,7 млн записей)
Формат `stats.txt`: для каждой длины окна — число окон, число различных паттернов и топ по частоте.

| Длина окна | Различных паттернов | Самый частый паттерн | Доля |
|---|---|---|---|
| 1 | 87 | `call <- or` | 28,1% |
| 2 | 233 | `call <- or ; call <- or` | 21,1% |
| 3 | 334 | `call <- or ; call <- or ; call <- or` | 19,0% |
| 4 | 409 | `call <- or ; call <- or ; call <- or ; call <- or` | 16,9% |
| 5 | 472 | `call <- or` ×5 | 14,7% |

- Доминирует `call <- or`: это `simPutPixel(x, y, argb)`, у которого цвет `argb` собирается через `or` в `heatColor`. Вызовы идут подряд, пока `drawField` рисует блок 4×4 пикселя одним цветом.
- Вторая группа — упаковка цвета в `heatColor`: `trunc <- shl ; or <- trunc` и `sub <- and ; mul <- sub ; ashr <- mul ; add <- ashr` (интерполяция каналов палитры).
- Третья — шаг диффузии: цепочки `add <- load`, `load <- getelementptr`, `getelementptr <- getelementptr`.
- Раскрытие `phi` убирает записи вида `getelementptr <- phi` (1,5%) и `add <- phi` (1,2%) и заменяет их записями по реальным источникам значений: число записей меняется с 46,29 млн до 46,67 млн.
