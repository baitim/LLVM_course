# Система команд

Набор команд составлен по статистике из [HW2](../HW2/stats.txt) (10 кадров, 46,7 млн записей `User <- Operand`) и по LLVM IR логики из HW1 (`../HW1/app.ll`). Приложение целиком переписано на эти команды: [app.s](app.s).

## Модель машины
- 32 регистра `x0`..`x31`, каждый 32 бита. Все значения целые, арифметика с переполнением по модулю 2^32.
- Память из 65600 32-битных слов. Адрес — номер слова, а не байта.
- Программа — список команд с метками. Метка — строка из одного слова, комментарий начинается с `#`.
- Непосредственные операнды 32-битные, можно писать в десятичном виде и в шестнадцатеричном (`0xFF000004`).
- Условный переход не имеет второй метки: если условие не выполнено, выполняется следующая команда.
- Программа должна заканчиваться командой `JMP` или `EXIT`.

Окно графического интерфейса, генератор случайных чисел и вывод кадра доступны только через команды `PUT_PIXEL`, `RAND` и `FLUSH`.

## Команды
В формате `x` — регистр, `imm` — число, `L` — метка. У арифметических команд есть вариант с непосредственным операндом: к имени добавляется `i`, третий аргумент становится числом (`ADD x1 x2 x3`, `ADDi x1 x2 5`).

### Арифметика и логика: `OP xd xa xb` / `OPi xd xa imm`
| Команда | Действие | Инструкция LLVM IR |
|---|---|---|
| `ADD` | `xd = xa + xb` | `add` |
| `SUB` | `xd = xa - xb` | `sub` |
| `MUL` | `xd = xa * xb` | `mul` |
| `DIV` | `xd = xa / xb`, знаковое | `sdiv` |
| `REM` | `xd = xa % xb`, знаковое | `srem` |
| `AND`, `OR`, `XOR` | побитовые операции | `and`, `or`, `xor` |
| `SHL` | `xd = xa << xb` | `shl` |
| `SHR` | `xd = xa >> xb`, арифметический | `ashr` |

### Пересылка
| Команда | Действие |
|---|---|
| `MOV xd xs` | `xd = xs` |
| `MOVi xd imm` | `xd = imm` |

### Память
Адрес считается как `xa + imm` (в словах). Он заменяет пару `getelementptr` + `load`/`store` из IR.

| Команда | Действие | Инструкция LLVM IR |
|---|---|---|
| `LD xd xa imm` | `xd = MEM[xa + imm]` | `getelementptr` + `load` |
| `LDADD xd xa imm` | `xd = xd + MEM[xa + imm]` | `getelementptr` + `load` + `add` |
| `ST xs xa imm` | `MEM[xa + imm] = xs` | `getelementptr` + `store` |

### Составные команды (по статистике)
| Команда | Действие | Инструкции LLVM IR |
|---|---|---|
| `LERP xd xa xb xf` | `xd = xa + (((xb - xa) * xf) >> 16)` | `sub`, `mul`, `ashr`, `add` |
| `EXTB xd xa xb` | `xd = (xa >> xb) & 255`, логический сдвиг | `lshr`, `and` |
| `ORSHL xd xa xb` | `xd = xd \| (xa << xb)` | `shl`, `or` |

### Внешние функции
| Команда | Действие |
|---|---|
| `PUT_PIXEL xx xy xc` | `simPutPixel(xx, xy, xc)` |
| `RAND xd` | `xd = simRand()` |
| `FLUSH` | `simFlush()` |

### Поток управления
| Команда | Действие |
|---|---|
| `BEQ xa xb L`, `BNE`, `BLT`, `BGE` | переход на `L`, если `xa == xb`, `xa != xb`, `xa < xb`, `xa >= xb`. Сравнение знаковое. |
| `BEQi xa imm L`, `BNEi`, `BLTi`, `BGEi` | то же с числом вместо `xb` |
| `JMP L` | безусловный переход |
| `EXIT` | завершить программу |

Это `icmp` + `br` в IR.

## Откуда взяты команды
В скобках доля от всех записей для окон длины 1 и для окон из двух записей (`a ; b`).

| Команда | Закономерность в статистике HW2 |
|---|---|
| `PUT_PIXEL` | `call <- or` — 28,08 %, `call <- trunc` — 5,62 %. Это вызов `simPutPixel`, самая частая запись; три аргумента берутся из регистров. |
| `LD`, `ST` | `load <- getelementptr` — 5,78 %, `getelementptr <- getelementptr` — 4,31 %, `getelementptr <- add` — 1,50 %, `getelementptr <- sext` — 1,40 %. Адрес вычисляется заранее, поэтому он вынесен в саму команду в виде `регистр + число`. |
| `LDADD` | `add <- load` — 3,67 %, окно из двух: `add <- add ; add <- load` — 2,20 %. Сложение пяти соседних клеток в `diffuseStep` — это цепочка `load` + `add`. |
| `LERP` | цепочка `sub <- and`, `mul <- sub`, `ashr <- mul`, `add <- ashr` (по 4,21 %, 4,21 %, 2,11 % и 1,41 %). В окне из трёх: `mul <- sub ; ashr <- mul ; add <- ashr` — 1,40 %. Это интерполяция канала цвета в `heatColor`. |
| `EXTB` | `lshr <- load ; and <- lshr` — 2,81 %. Выделение байта цвета из палитры. |
| `ORSHL` | `trunc <- shl ; or <- trunc` — 2,11 %. Упаковка канала в итоговый цвет. |
| `ADD`, `SUB`, `MUL`, `SHL`, `SHR` и варианты с числом | `add <- add`, `mul <- sub`, `shl <- add` и другие арифметические записи из первых строк статистики. |
| `DIV`, `REM` | `sdiv` и `srem` из IR. В приложении нужны `DIVi` (деление на 5 в `diffuseStep`) и `REMi` (остатки от `rand()` и номера источника). |
| `AND`, `OR`, `XOR` | побитовые инструкции IR. В `app.s` не используются (их работу в цвете выполняют `EXTB` и `ORSHL`), оставлены для полноты набора: у каждой арифметической операции есть вариант с регистром и вариант с числом. |
| `RAND`, `FLUSH` | вызовы `simRand` и `simFlush` из IR. |
| `BLT`, `BGE`, `BLTi`, `BGEi`, `BEQi`, `BNEi`, `JMP` | каждый цикл в IR заканчивается парой `icmp` + `br`; она заменена одной командой. Остальные команды сравнения (`BEQ`, `BNE`) нужны для полноты. |

Не вошли в набор:
- `phi` — в ассемблере значения лежат в регистрах, `phi` разворачивается в присваивания.
- `call` функций логики (`heatColor`, `diffuseStep`, `applyDisc`, `rotate`, `drawField`) — все они встроены в одну программу. Выход из `applyDisc` (два места вызова) устроен через регистр `x10` и условный переход.
- `sext`, `zext`, `trunc` — все значения 32-битные, преобразований типов нет.
- `alloca` — массивы лежат в памяти по фиксированным адресам (см. комментарий в начале [app.s](app.s)).

## Как приложение отображается на команды
| Часть `app.c` | Команды |
|---|---|
| `heatColor` | `MULi`, `SHRi`, `SHLi`, `SUB`, `LD` по палитре, цикл по трём каналам: `EXTB`, `LERP`, `ORSHL` |
| `diffuseStep` | `LD`, четыре `LDADD`, `DIVi`, `ST`, указатели увеличиваются через `ADDi` |
| `applyDisc` | `MUL`, `ADD`, `BLT`/`BLTi`/`BGEi` для проверки границ, `ST` |
| `rotate` | `LD`, `SHR`, `SUB`, `ADD`, `ST` |
| `drawField` | `PUT_PIXEL` в двух вложенных циклах 4 × 4, затем `FLUSH` |
| инициализация и вспышка | `RAND`, `REMi`, `ADDi`, `SUB`, `SHLi`, `ST` |
